# 问道科研 · Research Cultivation OS v2.3.0

> Windows 普通用户：从 [Releases 最新版本](https://github.com/yanjj5521/research-cultivation-os/releases/latest) 下载 `ResearchOS-*-Windows-x64.exe`。负责团队联机中心的人另下 `ResearchHub-*-Windows-x64.exe`；Android 用户下载同一 Release 中的 `ResearchOS-Mobile-*-Android.apk`。Windows 两个 EXE 均可直接双击，不要求 Python、pip 或管理员权限。

一个本地优先、交付驱动、面向整个科研生涯的个人成长系统。知识库只是它的长期记忆层；真正的核心是让方向判断、近期行动、证据、失败、能力、成果和阶段转向彼此继承。ResearchHub 可按需连接小团队，未开启时个人端仍完整可用。

它不是另一个待整理的资料仓库，也不是靠连续签到制造焦虑的打卡器。它把检索、计划、交付、复盘和长期科研资产连接为一条可重复流程：

```text
打开首页
→ 搜自己的知识或联网找论文
→ 进入今日修炼
→ 留下真实交付
→ 次日从记忆中提取
→ 把失败、决策、能力和成果写入生涯罗盘
→ 下一阶段继续调用过去积累的证据
```

修仙外观可以自定义，经验规则和科研数据结构保持稳定；漏一天不会清空长期成长，奖励只来自可追溯的真实行动。

## 修炼任务与每日任务

两类任务使用不同数据和完成标准：

- **修炼任务**：跨天的能力或成果里程碑，例如“能够独立判读 CV 曲线”“形成可复现 LJ 案例”；必须提交验收证据才可完成。
- **每日任务**：某一天可执行的下一行动，例如“判读一张曲线”“补齐 README”；通过当天真实交付完成。
- 每日任务可以关联并推进修炼任务，但不会自动替用户宣布里程碑完成。
- 一份 AI 文案可同时包含“修炼任务”和 `Day N` 计划，导入后仍分别保存。

经验值不再由计划文本或表单决定。导入文案里的 `XP / 经验 / 修为` 会被忽略；每日任务按时长档位统一计算，修炼任务按小成 / 进阶 / 突破统一计算。

## 每个人自己的工作区

默认提供 EG 实验、LAMMPS、数据集、ML、MD 与 COMSOL 六个模板，不再假定所有用户拥有相同方向：

- 可新建、改名、排序、换色、停用工作区，并选择是否固定到首页；
- 可选择通用知识专题、实验台账、模拟案例、数据集、ML、MD 或 COMSOL 类型；
- 每个工作区可自定义当前目标、4–6 步科研流程，以及论文、笔记、附件、任务、实验、模拟、数据集、文件夹和专注计时等组件组合；
- 导航根据本人的工作区动态生成；
- 工作区定义进入 v6 个性化包；记录和附件仍进入完整备份与知识库导出。

ML 工作区强调数据版本与拆分、特征管线、运行参数、指标、产物、误差分析和模型谱系；LAMMPS/MD 固化结构、势函数/力场、版本、输入、运行命令、日志、轨迹和判定标准；数据集先记录来源、许可、字段单位、缺失异常和版本；COMSOL 保留物理假设、材料来源、边界条件、网格无关性、求解器、基准与实验校核。

## 公开发行与开发工作区

- GitHub `Releases` 是普通用户唯一需要接触的公开下载入口；
- `main` 只接收已经通过回归、打包自检和数据迁移测试的稳定版本；
- 未完成开发不直接堆在 `main`，应保存在本机独立开发工作区或单独的私有仓库；
- 发布流水线在 Windows runner 上构建个人端与中心端两个 one-file EXE，在 Android runner 上测试、Lint 并构建 APK，最后统一上传双 EXE、APK、完整 ZIP 与 `SHA256SUMS.txt`；
- 每个正式版本同时在公开仓库与私有开发仓库建立 `release/vX.Y.Z` 快照分支，旧版分支不覆盖；
- GitHub 的公开仓库分支都是公开的，不能用一个所谓“开发分支”隐藏源码。需要保密时必须使用另一个私有仓库。

## 管理员与联机稳定性

- 轻量中心第一次启动时，如数据库中没有管理员，只自动创建一个 `admin`；随机密码与 Token 暂存在主机本地的 `instance/HUB_ADMIN_CREDENTIALS.txt`，并在支持 POSIX 权限时收紧为仅当前账户可读。
- 管理员首次登录后修改密码，系统会销毁一次性凭据文件；Token 仍可在“我的联机主页”查看或重新生成。
- 管理员只能管理邀请码、成员启停、版本包、中心备份与同步审计，不能读取成员电脑上的论文、实验、数据集或附件。
- 自动同步最多等待 1.5 秒；临时错误使用指数退避与抖动并遵守中心 `Retry-After`；连续 3 次失败后至少熔断 5 分钟；单事件 6 次失败转为人工恢复。
- 地址、Token 等永久错误不会无限重试；所有事件都有唯一编号，重复发送不会重复奖励或重复写入。
- 公网中心必须使用 HTTPS；明文 HTTP 只允许本机或私有局域网。关闭联机后不会新建同步队列。

### 一键导出知识库

知识库导出不是数据库黑盒，而是一个可直接阅读的 ZIP：

- 每条记录一份 CommonMark 友好的 Markdown；
- 完整结构化 `knowledge.json`；
- 原始附件；
- 课题推进、生涯节点、工作区、实验、模拟和复盘关键文本索引；
- 不包含游戏资产、API 密钥、联机 Token 或程序。

需要完整恢复时仍使用“完整备份”；需要带着全部程序迁移时使用“整套便携迁移包”。

## 核心科研闭环

```text
AI 生成 3–7 天近期计划
→ 粘贴导入
→ 完成任务并上传真实交付
→ 同时留下 3–8 条复盘关键文本
→ 下次打开主页弹出延迟复盘
→ 开放题回答、证据核对、本人确认掌握度
→ 特殊任务获得分级灵草
→ 在独立秘境中做综合迁移；到大境界门槛时才开启雷劫
```

### 近期计划

- 不再建立不可变的长期主线；
- 网站根据当前目标、未完成事项、最近交付和状态生成提示词；
- 将提示词复制给任意大模型，粘贴模型返回的 Markdown 即可导入；
- 提示词明确区分跨天里程碑与当天行动，且禁止模型输出经验值；
- 新计划可以随时替换旧计划，不产生“欠了几十天”的补课负担。

### 课题推进

- 课题不是不可变长期主线；可以并行建立、暂停、完成或停止；
- “课题定义完整度”只检查问题、目标、成功标准、当前基础与检索词是否齐全；
- “课题进度”只按通过的证据闸门计算，空白闸门不能直接标记通过；
- 相关论文只保存公开元数据与 DOI/来源链接，全文仍由用户自行下载和管理；
- 从当前闸门生成的三日计划会进入现有近期计划导入链，不另造一套每日任务。

### 交付驱动复盘

- 每次任务可以上传文字、文件或完整文件夹；
- “复盘关键文本”会作为 `复盘关键文本.txt` 放入该次交付目录；
- 自动复盘只读取这段关键文本，不扫描全部论文、实验数据或私人资料；
- 参考证据在回答后才显示；
- 开放题按证据和评分点给出部分得分、反馈与置信度，最终掌握度由本人确认。

### 秘境与突破

- 特殊任务按 1–5 级产生凡品、灵品、玄品、地品和天品灵草；
- 灵草可炼制清心丹、凝元丹与渡劫丹；
- “万象秘境”是独立综合试炼，不再混在复盘页；
- 五问雷劫只在金丹以上、修为达到下一大境界门槛时出现，均分达到 70 分才解锁突破；
- 秘境与雷劫只从用户自己的复盘材料中出题；
- 游戏奖励不能替代交付，所有资源都应能追溯到真实行动。

### 可迁移个性化

- 网站名、39 阶境界名、全部导航名、诗句池、工作区定义、主题、主页信息和复盘开关可导出为 JSON；
- 个性化包不包含论文、数据、附件、API 密钥或联机 Token；
- v2.1 能导入 v1–v6 个性化包；v6 使用稳定境界键，并携带压缩头像、每日诗句池、工作区目标、流程、组件与首页固定；
- 升级时保留本地 SQLite 数据库和 `storage/` 中的科研文件。

## 快速启动

### Windows

公开发行版下载后直接双击：

```text
ResearchOS-v2.3.0-Windows-x64.exe
```

默认打开 `http://127.0.0.1:5000`。无需管理员权限，也不会调用系统 Python。

负责小团队联机中心的人下载并双击：

```text
ResearchHub-v2.3.0-Windows-x64.exe
```

中心默认使用端口 `5050`，首次运行会显示局域网地址和一次性管理员凭据。需要 U 盘模式、旧版数据迁移、双端同机启动或桌面快捷方式时，再下载同一 Release 中的完整 ZIP。

### Android

下载并安装：

```text
ResearchOS-Mobile-v2.3.0-Android.apk
```

APK 是 ResearchHub 的移动入口：先在一台电脑运行 `ResearchHub.exe`，再在手机输入窗口显示的局域网地址，或点击 Hub 页面底部的“一键打开”链接。局域网 HTTP 只允许私有地址；公网地址必须使用 HTTPS。手机端不复制个人 SQLite、论文、实验原始数据或附件。

源码开发模式仍可双击 `启动科研系统.cmd`，它会在当前源码目录创建 `.venv`；该 CMD 只用于开发和诊断，不作为普通用户发布入口。

### Linux / macOS

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python run_local.py
```

### 运行自检

```bash
python self_test.py
python hub_self_test.py
python online_integration_test.py
```

## AI 模式

系统始终可以在离线规则模式运行。外部模型不可用时，复盘和特殊任务会安全回退，不会阻止正常交付。

### 本地 Ollama

在“设置与备份”中选择“本地 Ollama 模型”，填写接口和模型名，例如：

```text
http://127.0.0.1:11434/api/generate
```

### OpenAI / Responses 兼容接口

1. 在系统环境变量中设置密钥；
2. 在网页设置中选择“外部 OpenAI / 兼容接口”；
3. 填写 Responses API 地址和你账号可用的模型名。

Windows CMD：

```bat
set OPENAI_API_KEY=你的密钥
启动科研系统.cmd
```

Linux / macOS：

```bash
export OPENAI_API_KEY="你的密钥"
python run_local.py
```

密钥只从 `OPENAI_API_KEY` 或 `RESEARCH_OS_AI_KEY` 环境变量读取。不要把密钥写进源码、JSON 个性化包或 GitHub。

## 数据保存位置

| 数据 | 默认位置 | 是否同步到轻量中心 |
|---|---|---:|
| 个人数据库 | 发行版：`%LOCALAPPDATA%\ResearchCultivationOS\instance\research_os.db`；源码模式：`instance/research_os.db` | 否 |
| 论文、图片、数据集 | 发行版：`%LOCALAPPDATA%\ResearchCultivationOS\storage\uploads\` | 否 |
| 每日与特殊任务交付 | 发行版：`%LOCALAPPDATA%\ResearchCultivationOS\storage\deliveries\` | 否 |
| 个人头像 | 发行版：`%LOCALAPPDATA%\ResearchCultivationOS\storage\profile\` | 否 |
| 模拟案例 | 发行版：`%LOCALAPPDATA%\ResearchCultivationOS\storage\simulations\` | 否 |
| 身份、主题、境界名、导航名、工作区定义 | SQLite / 个性化包 | 可选 |
| 灵石、法器、建筑等轻量状态 | SQLite | 可选 |
| Android 客户端 | 只保存所选 Hub 地址、登录 Cookie | 连接 ResearchHub |

SQLite 使用 WAL 模式；自动备份通过 SQLite Backup API 创建一致性快照。仍建议定期把完整备份复制到另一块磁盘或可信云盘。

选择“便携模式启动”时，全部数据改为放在发行文件夹的 `user_data/`，适合 U 盘或整目录迁移。程序更新与个人数据默认分离；从 v2.0 源码版迁移时使用发行包中的 `迁移旧版数据.cmd`。

## 联机扩展

默认模式为“关闭”：本机不会新增同步队列，也不会上传或拉取状态。`services/sync_backend.py` 提供统一适配器边界，`docs/scalable-sync-api.openapi.yaml` 固定未来云端的版本化契约；规模化服务器、统一登录与多租户数据库尚未实现。

已有小团队仍可显式选择“轻量同行会”兼容模式：

直接双击 `ResearchHub.exe` 或 ZIP 中的 `启动联机中心.cmd`，默认地址为 `http://127.0.0.1:5050`。

中心负责：

- 账号与公开主页；
- 轻量游戏资产；
- 个性化配置；
- 资料链接卡；
- 软件版本发布。

中心不承担公共网盘职责。大型科研文件继续由每位成员本地保存，或使用成熟的共享盘、对象存储和机构平台。
